# Sprint-Review-and-Retrospective-
Sprint Review and Retrospective essay 

Brief description: This Sprint Review and Retrospective sums up what I did on the SNHU Travel project using Scrum and Agile. It covers how I helped out as Product Owner, Scrum Master, and developer, how we used user stories, standups, acceptance criteria, and sprint reviews to build working features, how the team handled interruptions and changes while improving communication, and how we worked with tools like Jira and Miro.


Reflection

I interpret user needs by listening to stakeholders and end users, then using that feedback to create clear requirements for the team. In the SNHU Travel project, I listed user stories as types of user, the task, and the goal” to keep the focus on user value and make sure everyone shared the same understanding of what we were building and why. User stories also helped the team set acceptance criteria and a definition of done, which made it easier to confirm that a feature was complete, working as intended, and ready to deliver.

When I develop programs, I break larger goals into smaller, high-priority tasks and deliver working software in short cycles so feedback can guide improvements. I used Scrum and Agile practices to help our team plan sprints, track progress, and adjust when changes occurred, such as when our payment processor became unavailable, and we had to change how we accepted payments. I want to continue using sprint planning, daily standups to identify problems early, sprint reviews to get stakeholder feedback, and retrospectives to improve how the team works. Being a good team member means communicating clearly, having shared goals, and helping with problems so progress does not stall. It also means helping keep the work high quality by testing and doing code reviews, being flexible when plans change, and speaking up in retrospectives so the team can get better over time.
